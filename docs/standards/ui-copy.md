# Web 看板文案标准（ui-copy）

> 本文档定义 **Web 看板（`orchestrator/web_ui/`）面向用户可见文案**的标准。
> 一句话原则：**前端只回答"用户在这里能做什么、怎么用"，不解释系统是怎么设计/实现的。**

相关实现：`orchestrator/web_ui/index.html`、`orchestrator/web_ui/js/*.js`、`orchestrator/web_ui/style.css`。

---

## 1. 核心原则

**产品界面不是设计文档。** 禁止在页面上展示功能设计、内部架构、实现机制、接口/字段名。用户关心的是"我点这个会得到什么"，不是"系统内部怎么实现"。

| 允许写 | 禁止写 |
|--------|--------|
| 用户要做的操作说明（表单如何填、批量按钮作用） | 功能是如何设计的、由哪些模块组成 |
| 校验/错误提示（为什么被拒、怎么改） | 后端处理流程、数据如何流转 |
| 安全/不可逆提醒（只显示一次、旧 token 失效） | 内部接口名、字段名、表名、存储细节 |
| 面向管理员的字段含义（用 `?` tooltip） | 心跳/队列/轮询/注册表等内部机制 |

## 2. 禁止的内部术语（示例）

文案中**不得出现**（除非是用户必须要懂的对外概念）：

- 机制类：`心跳`、`轮询`、`队列`、`入队`、`重新入队`、`注册表`、`迁移`、`原子更新`
- 接口/字段类：`REST`、`API 接口`、`GET/POST …`、`SKILL.md 元数据`、`effective_description`、`list_agents`、`token_hash`、`config-sync`
- 实现类：`边沿 agent 通过…接口浏览`、`节点据此生成…`、`保存后通过心跳同步到节点`、`仅元数据`

> 对外概念（如「节点」「任务」「技能」「团队」「token」）是产品语言，允许使用；内部机制不是。

## 3. 文案放在哪

1. **操作指引**：放在对应控件附近，或放在弹窗内的操作说明（`refresh-hint`），**只描述操作**。
2. **字段/配置含义**：放标题旁的 `?` tooltip（`<span class="help" data-tip="…">?</span>`），不铺成段落。
3. **不要**在页面（tab）里放整段介绍功能的文字；产品里没有"功能设计说明"。

## 4. 反例 → 正例

| ✗ 反例（设计说明，已删除） | ✓ 正例 |
|---|---|
| 技能库页：*上传的 zip 会被提取 SKILL.md 元数据（name/description）；边沿 agent 通过摘要接口浏览、按需下载使用。* | 删除（页面无需解释） |
| 团队页：*团队用于权限归属：节点访问权限、模板归属、任务可见性都可按团队。一个用户至多属于一个团队。* | 删除 |
| 模板页：*模板是节点的可复用配置（提示词 / 默认模型 / 权限 / 节点描述）。节点绑定模板后自动继承…* | 删除 |
| 用户页：*用户 API token 用于 REST 接口；丢失后可由管理员轮换…* | 删除 |
| Tooltip：*…保存后通过心跳同步给在线节点，节点级配置优先。* | *…节点级配置优先。* |
| Tooltip：*主 Agent 通过 list_agents 的 effective_description 看到。* | *供选择节点时参考。* |
| 保存提示：*已保存，将随心跳同步到节点* | *已保存* |
| 字段标签：*探针版本* | *版本* |

允许保留的"用户操作/安全"类文案（示例）：`每 5 秒自动刷新`、`API token 只显示这一次，请立即保存`、`留空 = 永久`、权限 JSON 的填写格式与示例、批量操作的"自动跳过/取消勾选即移除"说明。

## 5. 新增/修改 UI 文案的自检清单

- [ ] 这句话是在说"**用户能做什么 / 会看到什么**"，还是在说"**系统怎么实现**"？后者删掉。
- [ ] 有没有出现第 2 节的内部术语？有就改写或删除。
- [ ] 是整段功能介绍吗？是就删掉（必要时压缩成 `?` tooltip）。
- [ ] 是表单/校验/安全提示吗？保留并保持简洁、面向操作。

> 评审一个 UI 改动时，请一并按本清单检查新增文案。
