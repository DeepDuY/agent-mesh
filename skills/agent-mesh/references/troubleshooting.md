# 故障速查与安全

## 常见现象 → 原因 / 处理

| 现象 | 原因 | 怎么处理 |
|------|------|----------|
| `401 Unauthorized` | token 过期/失效 | 向用户说明，请其在控制台「个人中心」重新生成 token 并更新 `.env`；**不要反复重试**（见 [auth.md](auth.md)） |
| 派发返回 `403`（`command denied by permission policy`）或任务摘要含「权限被拒绝」 | 节点权限策略拒绝该命令 | 如实说明是权限策略；**不要尝试改权限/换模板**（那是管理员在页面做的事）。该次尝试会以「已拦截」状态保留在任务列表 |
| 任务一直 `queued` | 目标节点离线，或已达并发上限 | 换在线节点 / 等待（见 [nodes.md](nodes.md)） |
| `no LLM model configured` | 节点无可用模型 | 让管理员在控制台配置模型 |
| `attachment download failed` | 文件库文件被删或 md5 不符 | 重新上传文件（见 [files.md](files.md)） |
| `agent not found` / `task not found` / `404` | 节点/任务不存在，或你无权访问（无权限统一返回 404） | 确认标识正确，或请管理员授权；**不要尝试绕过** |
| 产物下载 `404` | 产物不属于你可访问的任务，或已被清理 | 核对 `task_id`/`artifact_id` 与任务归属 |

## 安全

- **可见性按身份隔离**：你只能看到/操作被授权的节点，以及自己（或本团队）的任务与文件；无权访问的资源返回 404（如同不存在）。
- 保管好 token；生产环境用 HTTPS。
- **不要调用管理面接口**：模板/权限、全局配置、用户管理，以及节点的编辑类操作（改别名/描述、升级探针、安装/删除节点）。它们不对外开放或属于管理员职责。
- **破坏性操作执行前先和用户确认**：取消任务（会杀掉远程进程组）、删除文件、删除任务。
